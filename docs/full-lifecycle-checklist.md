# Full lifecycle checklist

Use this document to prove coverage. Mark each row `N/A` only with a written reason and source.

| Stage | Required artifact | Pass condition | Primary owner |
|---|---|---|---|
| Mandate | Constraints and autonomy boundary | Platform, territory, budget, deadline, prohibited models, and human limits recorded | Human + agent |
| Discovery | Opportunity matrix | Diverse markets searched; direct evidence and adversarial counter-case recorded | Agent |
| Idea validation | Frozen thesis and experiment ledger | Behavioral gate precommitted and passed, or explicit risk acceptance recorded | Agent + human decision |
| Product specification | Versioned product contract | Core job, journeys, states, device support, monetization, data, non-goals, and acceptance tests complete | Agent |
| Brand/identity | Name and rights record | App name, domain/social handles, trademark conflicts, asset provenance, and bundle/SKU plan checked | Agent + human/legal where needed |
| Design | Screen/state/device matrix | Every common task usable across supported widths, orientations, text sizes, accessibility modes, and inputs | Agent |
| Account | Account readiness record | Membership, roles, agreements, paid status, tax/banking, trader/compliance declarations verified | Human attestations + agent verification |
| Toolchain | Reproducible environment | Current Xcode/SDK, MCP/CLI, simulator/device, secrets boundary, and fallback commands verified | Agent |
| Implementation | Traceability matrix | Every shipped promise maps to real code and tests; no placeholder or mock behavior | Agent |
| Security/privacy | Data/SDK/permission/claim/provenance register | Binary, code, policy, labels, manifests, traffic, website, and vendors agree | Agent + qualified review where triggered |
| Release testing | Candidate evidence pack | Same commit/build passes automation, devices, visual QA, persistence, account, network, StoreKit, archive, and TestFlight gates | Agent + human device checks |
| Store metadata | Field dossier | Every localization, URL, media asset, rating, privacy answer, review path, and availability field saved and reconciled | Agent + human attestations |
| Submission | Submission manifest | Correct version/build/dependent items listed; no unresolved stop-ship; authorized submission completed | Human or authorized automation |
| Review recovery | Incident packet | Exact message reproduced, systemic fix verified, invalidated gates rerun, precise response prepared | Agent |
| Release | Public verification | Intended storefront shows the version; clean device can download and complete paid/core flows | Human authorization + agent verification |
| Launch | Controlled experiment | Attribution, truthful creative, budget/stop rules, support, incident response, and channel plan active | Agent + human spend authority |
| Learning | Cohort decision record | Acquisition, activation, payment, retention, refund, support, crash, and proceeds evidence drives next decision | Agent + human decision |
| Maintenance | Update/compliance schedule | SDK/policy/OS/account/renewal/dependency triggers and vulnerability/support owners assigned | Agent + human owner |

## Validation evidence hierarchy

Do not substitute a weaker signal for a stronger one:

1. Search volume, complaints, and competitor reviews establish a hypothesis.
2. A qualified CTA establishes message interest.
3. Completion of the core job establishes activation.
4. A real purchase establishes willingness to pay.
5. Repeated use, renewal, or durable outcome establishes retention.
6. Cohort contribution after refunds, fees, support, and acquisition cost establishes business viability.

## Final completion test

Before declaring success, answer all of the following with evidence from the same version:

- Is the selected idea behaviorally validated for an MVP, or did the human explicitly accept the remaining uncertainty?
- Does every marketed feature exist and work?
- Can every supported device complete every common task?
- Do code, binary, backend, website, policies, privacy answers, manifests, and SDK behavior agree?
- Can a clean user download, activate, purchase, restore, delete their account where applicable, and reach support?
- Are all Apple and human-only attestations complete?
- Is the intended version actually available in the intended storefronts?
- Are attribution, support, incident response, rollback, and post-launch decision thresholds active?

If any answer is unsupported, the system is not complete.
